포스터 요소 추출 OCR 실험

EasyOCR, PaddleOCR, 그리고 EasyOCR가 읽기 어려운 줄만 Paddle로 다시 읽는 혼합 방식이 포스터 표준 스키마의 요소를 얼마나 뽑아내는지 같은 조건에서 비교했다.

결론

  • PaddleOCR가 판독과 추출 모두에서 가장 높았다. test 140장, 2배 확대 입력 기준 정답 문구 문자 일치율은 PaddleOCR 83.4%, 혼합 70.1%, EasyOCR 63.3%다.
  • 핵심 4필드(축제명·시작일·종료일·장소)를 모두 맞힌 포스터는 PaddleOCR 5.3% (7/131), 혼합 3.0% (4/131), EasyOCR 0.0% (0/131)다. 짝 비교(정확 McNemar) p값은 Paddle 대 EasyOCR 0.015625, 혼합 대 EasyOCR 0.125, Paddle 대 혼합 0.453125.
  • 필드별로는 일정 74.8% (104/139)·연도 96.3% (129/134)가 비교적 잘 나오고, 축제명 25.0% (35/140)·장소 45.0% (59/131)는 낮다(PaddleOCR). 장식 글꼴 제목과 여러 줄 장소가 주된 실패 원인이다.
  • 기관·문의처·프로그램처럼 작은 글자 항목은 세 경로 모두 거의 읽지 못했다. 이미지 대부분이 약 443×627 px 축소본이라 판독 한계가 먼저 온다.
  • EasyOCR의 읽기 어려운 줄만 Paddle로 다시 읽는 혼합 방식은 EasyOCR보다 낫지만 Paddle 단독에는 못 미친다. 고칠 줄을 EasyOCR 탐지 결과에서 고르기 때문에 EasyOCR가 놓친 줄은 다시 읽을 기회가 없다.

실험 설계

세 경로에 같은 전처리 두 가지(rgb_1x 원본, rgb_2x LANCZOS 2배)를 적용하고, 결과 OCR 줄을 같은 규칙 추출기(poster_rules_v1, extract.py sha256 00ca28308021…)로 포스터 추출 표준 1.0 문서로 바꿨다. 규칙은 dev 60장만 보고 다듬은 뒤 고정했고, 아래 수치는 모두 손대지 않은 test 140장이다.

지표

  • 판독률: 정답 문구가 OCR 전체 문자열 어딘가에 있는 정도. 공백·문장부호를 빼고 준전역 편집거리로 1 − 오류/길이를 잰다. 추출 규칙과 무관한 엔진 성능이다.
  • 필드 정확도: 정답에 인쇄된 항목만 분모로 둔다. 축제명·장소는 공백·문장부호를 뺀 완전 일치, 일정은 월·일 일치, 연도·회차는 숫자 일치. OCR 글자를 고치지 않으므로 한 글자만 틀려도 오답이다.
  • 목록 필드: 기관(역할·이름 쌍), 전화번호, 링크, 운영 시각의 정밀도·재현율·F1.
  • 통계: 비율은 Wilson 95% 구간, 판독률은 포스터 단위 부트스트랩 2,000회 95% 구간, 경로 비교는 같은 포스터끼리 짝지은 정확 McNemar 검정(양측).

장비: Windows 11 노트북, Intel Core i5-1135G7(4코어 8스레드), RAM 16GB, GPU 없음. 정답은 AI 보조 판독 2단계(작성·검토) 초안이며 사람 최종 검토 전이다.

혼합 경로에서 일어난 일

  • test 140장에서 EasyOCR 줄 2662개 중 1023개(장당 7.3개)를 다시 읽었고, 그중 878개의 문자가 바뀌었다.
  • 선택 사유: 낮은 신뢰도 953회, 핵심 근거 확인 186회. 규칙이 핵심 필드를 못 찾은 포스터가 137장(98%)이다.
  • 재인식은 줄 단위 교체라 EasyOCR가 줄 자체를 놓쳤거나 줄을 잘못 나눈 경우는 고칠 수 없다. 장당 최대 8줄 제한도 작은 글자가 많은 포스터에서는 부족하다.

한계와 다음 단계

  • 해상도: 대부분 443×627 px라 작은 글자 결과는 엔진 성능보다 해상도 한계를 반영한다. 고해상도 원본 일부로 같은 비교를 다시 해야 한다.
  • 정답: AI 보조 판독 2단계 초안이다. 사람 검토 후 수치가 바뀔 수 있고, 블라인드 30장 일치도는 데이터 전처리 보고서에 있다.
  • 규칙 추출기: OCR 글자를 고치지 않는 보수적 규칙이다. 제목·장소처럼 문맥 판단이 필요한 필드는 VLM이나 OCR+LLM 연결이 필요하다.
  • 다음 실험: 같은 test 140장·같은 정답·같은 지표로 VLM(소형 로컬, RunPod 중형)을 추가한다. 설계는 docs/poster-ocr-vlm-testbed.md에 있다.

재현 명령

.\.venv\Scripts\python.exe -m app.poster_ocr.prepare_models
.\.runtime\easyocr-env\Scripts\python.exe app\poster_ocr\ocr_worker.py --engine easyocr --out data\runtime\poster-ocr\runs\easyocr --model-dir .runtime\easyocr-models
.\.runtime\paddle-env\Scripts\python.exe app\poster_ocr\ocr_worker.py --engine paddleocr --out data\runtime\poster-ocr\runs\paddleocr --model-dir .runtime\paddle-models
.\.venv\Scripts\python.exe -m app.poster_ocr.hybrid plan --easy data\runtime\poster-ocr\runs\easyocr
.\.runtime\paddle-env\Scripts\python.exe app\poster_ocr\paddle_rec_worker.py --crops .runtime\poster-ocr\hybrid-crops\crops.json --output .runtime\poster-ocr\hybrid-crops\paddle_rec.json
.\.venv\Scripts\python.exe -m app.poster_ocr.hybrid merge --easy data\runtime\poster-ocr\runs\easyocr --out data\runtime\poster-ocr\runs\hybrid
.\.venv\Scripts\python.exe -m app.poster_ocr.extract --ocr data\runtime\poster-ocr\runs\paddleocr --out data\runtime\poster-ocr\pred\paddleocr   # 경로마다
.\.venv\Scripts\python.exe -m app.poster_ocr.evaluate --out data\runtime\poster-ocr\eval\final.json
.\.venv\Scripts\python.exe -m app.poster_ocr.report experiment --eval data\runtime\poster-ocr\eval\final.json
