축제 포스터 추출 표준

포스터에서 무엇을 어떤 형태로 뽑을지 정한 팀 표준입니다. 실제 축제 포스터 38장을 직접 조사해 어떤 정보가 얼마나 인쇄되는지 확인하고, 그 결과로 필드와 규칙을 정했습니다. OCR·모델·사람 중 누가 추출하든 같은 JSON을 만듭니다.

결론

  • 모든 포스터에 있는 것은 축제명·일정·장소 셋뿐입니다. 요일도 37장에 있어 날짜를 제대로 읽었는지 확인하는 신호로 씁니다.
  • 일정 문구에 연도가 없는 포스터가 10장, 연도가 아예 없는 포스터가 3장입니다. 날짜를 연·월·일·요일·연도 근거로 나눠 저장하고, 연도가 없으면 API나 파일명으로 채우지 않습니다.
  • 기관은 모든 포스터에 있지만 역할 표기는 25장, 기관명을 모두 읽은 포스터는 15장입니다. 그래서 모든 항목에 '없음'과 '판독 불가'를 구분하는 상태를 둡니다.
  • 기존 2.1 계약의 좌표·장소 웹주소를 인쇄한 포스터는 0장입니다. 이 필드는 API 전용으로 두고 포스터 추출 대상에서 뺐습니다.
  • 요금은 0장이지만 광고 발주의 검수 항목입니다. 공공 지역축제에는 없고 유료 공연과 발주 기준(얼리버드 가격)에는 있어 조건부 필드로 남겼습니다.

포스터 38장에 인쇄된 요소

TourAPI 2026년 축제 813건에서 시·도별로 64건을 무작위로 뽑아 포스터가 있는 37장과 기존 강남페스티벌 포스터 1장을 봤습니다. 막대 색은 표준에서 정한 추출 등급입니다.

  • 포스터 제목과 TourAPI 제목이 기존 제목 정규화로도 다른 포스터가 6장입니다. 예: 두두썸동과 대구 동구 여름축제 두두썸동, DAEGU CHIMAC FESTIVAL과 대구치맥페스티벌.
  • 연도가 있는 35장 중 1장은 일정이 TourAPI와 다릅니다. 단양 겨울놀이 축제 포스터는 1.23~25 '3일간', API 종료일은 1.26입니다.
  • 인쇄 요일은 확인한 34장 모두 달력과 맞았습니다. 요일이 어긋나면 판독 오류나 포스터 오기일 가능성이 큽니다.
  • QR이 있는 9장 중 해독에 성공한 것은 고해상도(940 px) 1장뿐입니다. 해독하지 못한 QR의 주소는 추정하지 않습니다.
  • 2026 목록 813건 중 17건이 연도를 넘는 행사입니다. 기존 2.1 검증이 이런 포스터를 거부하던 문제를 고쳤습니다.

설계 원칙

  • 포스터에 인쇄된 것만 기록합니다. API·이미지명·파일명 값을 관찰값으로 쓰지 않습니다.
  • 모든 항목에 상태가 있습니다. present 읽음, illegible 있으나 판독 불가, absent 없음, not_checked 이번에 확인하지 않음. 검수에서 '없음'은 미충족, '판독 불가'는 확인 필요가 됩니다.
  • 원문·정규화값·근거를 함께 둡니다. 근거는 추출 방식, OCR 결과 ID, 원본 픽셀 좌표, 신뢰도입니다. 측정하지 않은 좌표와 신뢰도는 null로 둡니다.
  • 날짜를 나눠 저장합니다. 연도 미표기, 연도를 넘는 일정, 요일 대조를 한 구조로 처리합니다.
  • 제목·슬로건·영문명, 기관 이름·역할을 분리합니다. 글자 크기나 로고 위치로 의미를 추정하지 않습니다.
  • 시각·홍보 정보는 판정과 분리합니다. 그림 속 간판 글자가 9장, 세로쓰기가 4장이라 OCR 오추출 경고에만 씁니다.

JSON 구조

단일 값 항목은 {status, raw, 정규화값, evidence}, 목록 항목은 {status, items: [...]}로 통일했습니다.

├─ record_id · image(sha256, width, height) · coordinate_space
├─ extraction        status · method · extracted_at · extractor · notes
├─ title             raw · official · variants[english | brand | alias]
├─ edition · year    raw · number | value
├─ slogans           raw · headline

├─ venue             raw · items

공통 JSON 2.1과 연결

  • attach-poster가 표준 문서를 2.1의 poster 블록으로 바꿔 공통 레코드에 넣고, 이후 compare는 지금처럼 API와 비교합니다. 강남 예시는 연결 후 비교 결과가 기존과 같습니다.
  • 주최·주관·후원은 역할이 인쇄되고 이름을 읽은 기관만 2.1 필드로 옮깁니다. 역할 없는 로고는 details.logos에 unknown으로 갑니다.
  • OCR 근거가 있는 문서는 attach-ocr로 OCR 결과를 먼저 연결해야 하고, 근거의 OCR ID가 실제 결과에 있는지 확인합니다.
  • 표준 원본 파일은 2.1 레코드에 들어갈 자리가 없어 레코드 옆에 따로 보관합니다.
.\.venv\Scripts\python.exe scripts\collect_festivals.py validate data\festivals\examples\danyang.poster.standard.json --poster
.\.venv\Scripts\python.exe scripts\collect_festivals.py attach-poster --record data\festivals\examples\gangnam.common.final.json --poster data\festivals\examples\gangnam.poster.standard.json --output data\runtime\festivals\attached.json
.\.venv\Scripts\python.exe scripts\collect_festivals.py compare --poster data\runtime\festivals\attached.json --reference data\festivals\examples\gangnam.api.live.json --output data\runtime\festivals\final.json

팀이 정할 것

  • 공통 계약 3.0 2.1의 poster 블록을 이 표준으로 바꾸면 투영 단계와 별도 파일 보관이 없어집니다.
  • 사람 정답 형식 labels도 같은 구조로 두면 예측과 정답을 필드 단위로 바로 비교할 수 있습니다.
  • 검수 기준명 추가 주최·주관·후원·문의처·회차·예산 표기를 기준 문서 파서에 넣을지 정합니다.
  • 이미지 해상도 TourAPI 상세 이미지는 대부분 445 px라 기관·문의가 중요한 발주는 원본을 따로 받아야 합니다.
  • 조사 검토 38장 코딩을 두 사람이 교차 확인하고 유료 공연 포스터를 더 조사할지 정합니다.

조사 코딩과 예시 4개는 AI 보조 도구가 원본 이미지를 직접 보고 만든 1차 기록이며 사람 검토 전입니다. 학습·평가 정답으로 쓰지 않습니다.
