W01 · 요청 접수

요청 의도 분류

지금

요청 문장을 신규 검수·재검수·기준 변경·조회·기타로 나누는 단계가 없습니다. 합성 문장 250개(의도마다 50개)는 수집돼 있지만 라벨은 전부 초안 상태입니다.

왜 ML·DL인가

같은 뜻을 다르게 말하는 문장이 많아 키워드 규칙으로는 빠지는 표현이 생깁니다. 계획서도 분류 모델을 직접 학습하고 TF-IDF 기준 모델과 비교하도록 정해 두었습니다.

후보와 쓰는 법

  • TF-IDF + 로지스틱 회귀 ML 몇 초 만에 학습되는 기준선. DL 결과가 이보다 얼마나 나은지 보여 주는 용도.
  • klue/roberta-small · base DL 5분류 헤드를 붙여 미세조정. 예측 확률이 낮으면 분기하지 않고 확인 질문을 던짐.
  • XLM-R-large DL 표에서 가장 높지만 대형 다국어 모델이라 250문장 5분류에는 과함.

제안 TF-IDF 기준선과 klue/roberta-small을 먼저 돌리고, 차이가 없으면 base로 올리지 않습니다. 문장 250개는 의미 그룹 50개에서 5개씩 변형한 것이므로 학습·시험을 그룹 단위로 나눠야 수치가 부풀지 않습니다.

W04 · 시각 검사

객체 개수와 외관

지금

딸기 개수, 음료 외관, 크기별 크루아상 수량, 접시 외관 네 규칙은 검사기가 없어 '확인 필요 · 미실행'으로 남습니다. 세 주제 15개 규칙 가운데 4개입니다.

왜 ML·DL인가

개수와 모양은 OCR로 읽을 수 없고 규칙으로도 쓸 수 없습니다. 이미지 모델이 없으면 이 네 규칙은 계속 사람 몫입니다.

후보와 쓰는 법

  • Grounding DINO DL 'strawberry', 'croissant' 같은 글로 대상을 지정해 박스를 얻고 개수를 셈. 라벨 0장으로 시작. Apache-2.0.
  • YOLO11n · s DL 박스 라벨이 모이면 미세조정. 가볍고 빠름. Ultralytics 배포판은 AGPL-3.0이라 공개 범위 확인 필요.
  • RT-DETR-L DL 겹침 제거 후처리가 없는 검출기. 붙어 있는 빵처럼 겹친 대상에서 비교해 볼 후보.
  • 시각 언어 모델 DL 컵 모양·층 색 같은 외관 서술에 사용. 개수는 맡기지 않음.

제안 Grounding DINO로 라벨 없이 개수를 세어 보고, 검출 박스를 그대로 결과의 근거 영역으로 저장합니다. 검출 점수가 낮거나 대상이 가려지면 지금처럼 '확인 필요'로 둡니다. 사람이 고친 박스가 쌓이면 YOLO11 미세조정과 비교합니다.

W04 · 문자 검사

OCR 인식과 신뢰도 보정

지금

RapidOCR의 PP-OCRv5 한국어 인식 모델을 그대로 씁니다. 줄 신뢰도가 0.5 미만이면 판정을 보류하는데, 코드 주석대로 이 수치는 보정된 확률이 아닙니다. GPU 경로는 PP-OCRv4 인식 모델을 써서 CPU와 결과가 다를 수 있습니다.

왜 ML·DL인가

글자 하나를 잘못 읽으면 정상 광고가 '미충족'이 됩니다. 신뢰도가 실제 정답률과 맞아야 어디까지 자동 판정하고 어디부터 사람에게 넘길지 정할 수 있습니다.

후보와 쓰는 법

  • 신뢰도 보정 ML 줄 신뢰도와 정답 여부로 온도 스케일링이나 등위 회귀를 학습. 임계값을 '오판 1% 이하'처럼 목표로 정함.
  • 인식기 미세조정 DL 포스터 장식체에서 같은 오독이 반복될 때만. 글자 줄 이미지와 정답 전사가 필요.
  • 현행 유지 현재 비교 기준선. 장치(CPU·GPU)별로 따로 측정.

제안 모델은 바꾸지 않고 신뢰도 보정부터 합니다. 포스터 글자 줄에 정답 전사를 붙인 뒤 보정 전후의 ECE와 보류율–오판율 곡선을 나란히 보여 주면 됩니다. 미세조정은 문자 오류율(CER)에서 반복 오독이 확인된 뒤에 결정합니다.

W02 · 기준 문서

근거 검색 (RAG)

지금

검색 인덱스가 없습니다. 의뢰서·가이드·체크리스트 세 벌과 공통 FAQ, 합쳐서 문서 10건이 수집돼 있습니다.

왜 ML·DL인가

"할인 문구 예외가 있었나" 같은 질문은 문서의 표현과 단어가 달라 키워드 검색으로 놓칩니다. 뜻으로 찾으려면 임베딩 모델이 필요합니다.

후보와 쓰는 법

  • BM25 비학습 키워드 검색 기준선.
  • multilingual-e5-large DL 널리 쓰이는 다국어 임베딩. 비교 대상.
  • bge-m3 dense DL 계획서의 기본 선택. 조항 단위로 잘라 Qdrant에 적재하고, 프로젝트·문서 버전으로 먼저 거른 뒤 검색.
  • bge-m3 dense + sparse DL 같은 모델에서 키워드 신호를 함께 쓰는 하이브리드. 개선 폭을 보고 채택.

제안 BM25와 bge-m3 dense를 같은 질문 세트로 비교합니다. 질문마다 정답 조항 ID를 붙여 두면 Recall@5를 바로 잴 수 있습니다. 검색 결과는 근거 조회용이며, 검수 체크리스트는 확정 기준 전체를 DB에서 읽는다는 기존 규칙을 유지합니다.

W04 · 문자 검사

포스터 필드 추출

지금

기준 파일에 적어 둔 영역 좌표와 정규식으로 행사명·날짜·장소를 고릅니다. 샘플 포스터 배치에 맞춘 설정이라 배치가 다른 실제 포스터에는 영역을 새로 정해야 합니다.

왜 ML·DL인가

포스터마다 제목·날짜·장소의 위치가 다릅니다. 글자 내용과 위치를 함께 보는 모델이라야 처음 보는 배치에서도 필드를 찾습니다. 공통 JSON 2.1의 labels.event와 영역 라벨이 학습 데이터 형식으로 이미 정해져 있습니다.

후보와 쓰는 법

  • 텍스트 토큰 분류 DL OCR 줄의 글자만 보고 필드를 태깅. KLUE-RoBERTa로 시작하기 쉬움.
  • LiLT + 한국어 RoBERTa DL 글자와 박스 좌표를 함께 입력. 언어 모델을 바꿔 끼울 수 있는 구조.
  • LayoutLMv3 DL 벤치마크 최고 수준이지만 비상업 라이선스(CC BY-NC-SA 4.0).
  • 시각 언어 모델 구조화 출력 DL 라벨 없이 시작. OCR 인계 스키마로 구조를 검증. 근거 영역 연결은 따로 맞춰야 함.

제안 라벨이 없는 지금은 현행 규칙을 기준선으로 고정해 두고, 실제 포스터에 사람 승인 라벨이 붙는 대로 텍스트 토큰 분류와 LiLT를 비교합니다. 추출 결과는 poster.event와 evidence.ocr_ids에 채워 기존 검증 함수로 구조를 확인합니다.

수치를 내기 전에 맞출 것

  • 사람 승인 라벨이 0건입니다. 요청 250문장은 전부 초안이고 축제 레코드의 정답도 비어 있습니다. 승인 전 수치는 진단용으로만 씁니다.
  • 그룹 단위로 나눕니다. 요청 문장은 의미 그룹 50개, 이미지는 원본 그룹이 같은 것끼리 한쪽 분할에 둡니다. 섞이면 시험 점수가 실제보다 높게 나옵니다.
  • 합성 데이터의 한계를 함께 적습니다. 개발 샘플 18장은 AI로 만든 변형이라 일반화 성능으로 말할 수 없습니다.
  • 기준선을 먼저 고정합니다. 파트마다 현행 방식이나 가장 단순한 모델의 수치가 있어야 ML·DL을 넣은 효과가 보입니다.
