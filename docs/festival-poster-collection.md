# 축제 포스터 수집 방법 (2026-10-19 실측 기준)

최신 축제 포스터 200장을 OCR·VLM 평가용으로 모으는 절차다. 결론부터 적으면 **전국문화축제표준데이터 API에는 포스터가 없고, 포스터는 TourAPI `detailImage2`에서 대부분 자동으로 받을 수 있다.** 사람은 처음부터 찾지 않고, 자동 후보를 확인하고 빈 곳만 채운다. 평가 환경은 [포스터 OCR·VLM 테스트 환경](poster-ocr-vlm-testbed.md)을 따른다.

## 1. API별 포스터 제공 여부

| 출처 | 포스터 | 근거 |
| --- | --- | --- |
| 전국문화축제표준데이터 (data.go.kr 15013104) | **없음** | 표준 항목 15개+데이터기준일자에 이미지 항목 없음. 10-19 실제 호출도 1,364건·18개 필드로 이미지 필드 없음. 포스터 탐색에 쓸 수 있는 값은 `homepageUrl`뿐 |
| TourAPI KorService2 `detailImage2` | **있음 (주 출처)** | `originimgurl`, `imgname`, `serialnum`, `cpyrhtDivCd` 제공. 포스터 여부 필드는 없고 `imgname`의 "포스터" 문구가 유일한 신호 |
| TourAPI `searchFestival2`의 `firstimage` | 거의 아님 | 대표이미지가 포스터와 같은 경우: 표본 조사 4/37, 이번 표본 0/81 (CMS 이미지 ID 비교) |
| 한국문화정보원 한눈에보는문화정보 (data.go.kr 15138937) | 일부 | 기존 `DATA_GO_KR_SERVICE_KEY`로 호출 성공. `realmCode=F000`(행사/축제) 2026년 386건, `thumbnail`이 포스터 비율. 표준데이터 2026과 이름·날짜로 맞는 축제는 22건(약 2.8%)뿐이고 오매칭이 있어 사람 확인 필요. `http://`는 `https://`로 바꿔 받음 |
| 서울 열린데이터광장 문화행사 정보 | 서울만 | `MAIN_IMG`, 공공누리 1유형. 별도 서울시 키 필요 |
| KOPIS `prffest` | 공연예술 축제만 | `poster` 필드. 지역축제는 거의 없음. 별도 KOPIS 키 필요 |
| 대한민국 구석구석 축제 페이지 (kfes) | 사람이 확인할 때만 | API 없음. TourAPI에 이미지가 없는 축제에서 포스터가 보이는 사례 확인(3114696 강북구 어린이날 대축제). 라이선스 표시 없음 |
| 네이버·카카오 이미지 검색 API | 사용 안 함 | 보도 기준 네이버 검색 API 특약(2026-09-07 시행)이 AI 입력·평가를 금지(원문 미확인). 카카오는 사전 승인 없는 결과 재사용 금지. 사람이 클릭하는 검색 링크로만 사용 |

"API로 포스터를 받을 수 있다"는 이야기는 PR #9("API 기반 지역축제 포스터 50개")에서 나온 것으로 보인다. 해당 PR은 표준데이터 API로 **축제 목록을 고르고**, 포스터 파일은 구석구석(kfes) 페이지에서 직접 받았다.

## 2. 실측 커버리지

2026-10-19 실제 호출 결과다. 표본 비율은 실측, 전체 건수는 비율을 곱한 **추정**이다.

| 항목 | 값 |
| --- | --- |
| 표준데이터 2026 시작 행사 | 798행 (이름+시작일 기준 728건, 한국관광공사 제공 64행 포함) |
| TourAPI 2026 시작 행사 | 812건, 그중 `firstimage` 있음 806건 |
| 두 목록 매칭 (이름+기간 겹침+지역) | 표준데이터 280행 = TourAPI 218건. 표준데이터만 518행, TourAPI만 594건 |
| 매칭 축제 중 "포스터" 이름 이미지 보유 | 99/123 = **80.5%** (Wilson 95% 72.6–86.5%) → 약 175건 (추정) |
| TourAPI 전체 기준 | 약 **56%** (95% 45–68%) → 약 458건 (추정) |
| 상세 이미지 자체가 없는 축제 | 표본 13/64, 6/99 |
| 저작권 유형 | 표본 상세 이미지 981장과 `firstimage` 806건 모두 `Type3` (공공누리 제3유형) |

포스터 이름이 붙은 이미지는 37/37장이 세로형(세로/가로 1.25–1.46, 대부분 약 443×627px)이었다. 이름이 없는 세로형 이미지 12장 중 포스터는 2장뿐이고 나머지는 안내 카드뉴스·세로 사진이었다. 따라서 **이름 힌트는 자동 채택, 세로 비율은 사람 검토 순서 정렬에만** 쓴다. 정렬은 1.41(A판 비율)에 가까운 순이 맞다. 1.5(418×627)는 세로 사진 비율이고, 4:5 카드뉴스(약 1.25)는 포스터 경계와 겹친다.

**200장 목표에는 충분하다.** TourAPI 2026에서 포스터 이름 이미지가 약 458건(추정) 있으므로, 수작업으로 200장을 찾을 필요 없이 자동 후보에서 층화 선별 후 확인만 하면 된다. 해상도는 약 443×627px로 낮다는 점은 평가 설계에 반영한다.

## 3. 단계별 수집 흐름

| 단계 | 대상 | 사람이 하는 일 |
| --- | --- | --- |
| T1 자동 | `imgname`에 "포스터/poster"가 있고 다른 연도(20xx)가 없는 이미지 | 검토 화면에서 훑어보며 틀린 것만 거절 |
| T2 확인 | 상세 이미지는 있지만 이름 힌트가 없는 축제, 날짜가 충돌하는 동명 축제 6건, 포스터 이름 이미지가 여러 장인 축제 | 비율순으로 정렬된 후보 중 하나 선택하거나 "없음" 표시 |
| T3 다른 API | 문화정보원 F000 `thumbnail` | 반드시 확인 (오매칭 있음) |
| T4 수작업 | 나머지 | 작업 목록의 링크를 눌러 찾고 URL만 붙여 넣기 |

200장 수집에서는 T1 후보만으로 목표를 채우고, 지역·디자인 층화가 비는 칸만 T2–T4로 채우는 것이 가장 빠르다. 표준데이터 798행 전체를 채우려면 약 2/3가 수작업이므로, 그 경우에는 첫 20건의 실제 소요 시간을 재고 나서 범위를 정한다.

### 사람이 여는 파일

1. **`review.html` (T1–T3)**: 축제별 카드에 표준데이터의 행사명·기간(요일 포함)·장소와 후보 이미지를 보여준다. 이미지는 원본 URL로 표시만 하고, 채택한 것만 내려받는다. T1은 미리 채택된 상태로 열린다. `Enter` 채택, `1–9` 다른 후보 선택, `X` 연도 불일치·포스터 없음. 결과는 `decisions.json`으로 내보낸다.
2. **`worklist.csv` (T4)**: UTF-8 BOM으로 저장해 Excel에서 한글이 깨지지 않게 한다. 순서는 2026–2027 문화관광축제 27건 → `homepageUrl` 있는 행 → 나머지 순이다. `owner` 열을 시도별로 미리 채워 팀원끼리 나눈다.

`worklist.csv`의 미리 채우는 열: `wl_id`(행사명 키+시작일+기관코드 해시), 기대 기간·요일, 장소, 기관명, kfes 링크(`https://korean.visitkorea.or.kr/kfes/detail/fstvlDetail.do?cmsCntntsId={contentid}`), `homepageUrl`, "2026 {축제명} 포스터" 검색 링크, `license=unknown`.

### T4 한 건당 작업 (2–3번 조작)

1. kfes → 홈페이지 → 검색 링크 순서로 첫 번째로 열리는 링크를 누른다.
2. 포스터의 이미지 주소를 `image_url`에, 페이지 주소를 `page_url`에 붙여 넣는다. 인스타그램처럼 이미지 주소가 고정되지 않으면 `intake/<wl_id>.<확장자>`로 저장한다. 같은 축제의 두 번째 판은 `<wl_id>__2.<확장자>`.
3. 페이지에 공공누리 표시가 있을 때만 `license`를 `kogl1`–`kogl4`로 바꾼다. 못 찾으면 `status=no_poster`로 표시해 다시 찾지 않게 한다.

해시·크기·형식·수집 시각·수집자·출처 URL·API 원본 항목은 `ingest`가 자동 기록한다. 사람이 입력하지 않는다.

### 중복과 연도 오류 방지

- 같은 TourAPI 축제에 묶인 표준데이터 행(62행, 그중 47행이 한국관광공사 제공 중복)은 작업 목록에서 한 줄로 합친다.
- `sha256`은 등록부 전체에서 유일해야 한다. 다른 축제에 같은 해시가 나오면 `ingest`가 멈춘다. main의 기존 `data/img/` 200장도 등록부에 먼저 넣어 중복을 막는다.
- 재인코딩된 사본은 dHash 유사도 경고로 잡는다 (선택).
- 카드와 작업 목록에 기대 기간과 요일을 항상 보여주므로 확인자는 "포스터 날짜가 이것과 맞는가"만 본다. 수집 후에는 기존 `poster.weekday_years`와 `compare`가 날짜 모순을 다시 표시한다.

## 4. 라이선스와 저장 규칙

TourAPI 이미지는 공공누리 **제3유형(출처표시·변경금지)**이다. 상업적 이용은 가능하지만 형태 변경을 포함한 모든 변경이 금지된다 ([공공누리 제3유형](https://www.kogl.or.kr/info/licenseType3.do)). 한국관광콘텐츠랩 저작권 정책은 콘텐츠 캐싱(로컬서버 저장)을 금지하고, 자체 서버에 저장하는 방식은 별도 신청(tourapi@knto.or.kr)으로 안내한다 ([저작권 정책](https://api.visitkorea.or.kr/#/useServiceGuide/2), [FAQ](https://api.visitkorea.or.kr/#/cmsFAQ)).

| 행위 | 규칙 |
| --- | --- |
| 원본 저장 | Git 제외 폴더(`data/runtime/`)에만 저장하고, Git에는 URL·`sha256`·`cpyrhtDivCd` 등 메타데이터만 올린다. 학생 프로젝트의 로컬 연구 사본이 허용되는지는 공식 문구가 없어 해석의 영역이다 |
| 잘라내기·크기 변경 후 저장·공개 | 금지. 전처리는 메모리에서만 하고 crop·오버레이 이미지는 공개하지 않는다 |
| OCR·VLM 평가 | 새 이미지를 만들지 않는 사실 판독이지만 공식 해석은 없음(불확실). 내부 평가로 한정 |
| 모델 학습 | 명시적으로 허용되지 않음. 학습에 쓰려면 먼저 한국관광공사에 문의 |
| 데모 화면 | 원본 그대로(잘림 없이 `object-fit: contain`) "출처: ⓒ한국관광공사" 표시와 저작권 정책 링크 |

kfes·지자체 홈페이지·인스타그램 포스터는 공공누리 표시가 없으면 `license=unknown`으로 기록하고 내부 평가에만 쓴다.

> **팀 확인 필요:** 현재 GitHub 저장소는 **PUBLIC**이고, main의 `data/img/`에 포스터 200장이 커밋되어 있다(PR #9 등). PR #9도 재배포 허가를 "미확인"으로 적었다. 저장소 비공개 전환·허가 요청·파일 제거 중 하나를 팀이 정해야 한다. 파일을 지워도 Git 기록에는 남는다. 이 문서 작성 중에는 아무것도 변경하지 않았다.

## 5. 호출 한도와 일괄 수집

- TourAPI 개발계정은 하루 1,000건이며 00시에 초기화된다. 운영계정은 기본 하루 100,000건이고 심사에 약 1주가 걸린다 ([이용 안내](https://api.visitkorea.or.kr/#/useServiceGuide/1)).
- 2026년 전체는 `searchFestival2` 1건(`FESTIVAL_PAGE_SIZE=1000`)과 `detailImage2` 약 812건이므로 하루 한도 안에 들어가지만 재실행할 여유가 없다. 10-19에는 이미 약 110건을 썼으므로 전체 실행은 다음 날 한다.
- 축제마다 `cache/tourapi-detail/<contentid>.json`을 바로 저장하고 `--resume`으로 저장된 건을 건너뛴다. `--max-calls 900`은 재시도를 포함해 센다. 한도·인증 오류가 나면 즉시 멈춘다 (현재 `collect`는 축제별 오류를 기록하고 계속 호출한다).
- 매칭된 218건을 먼저 처리하고 나머지를 처리한다. 포스터 힌트 이미지만 내려받으면 약 460장으로 줄어든다.
- `TOURAPI_MOBILE_APP`을 팀 고유 값으로 바꿔 두면 운영계정 신청에 유리하다.
- 이미지 다운로드(`tong.visitkorea.or.kr`)는 서비스 키를 쓰지 않으므로 API 한도에 포함되지 않는 것으로 보이지만 공식 문구는 없다.

## 7. 아직 확인하지 못한 것

- 「공공데이터 제공 표준」 20차 개정 전문(.hwpx)을 내려받지 않아 문화축제 표준의 개정 여부는 모른다. 다만 현재 페이지와 API에는 이미지 항목이 없다.
- kfes·문화정보원으로 수작업 단계를 얼마나 줄일 수 있는지는 측정하지 않았다.
- 한국관광콘텐츠랩 웹 다운로드(개인회원 940×627 안내)가 API 포스터(약 443px 폭)보다 큰지는 확인하지 않았다.
- 포스터 판정은 627px 축소본을 눈으로 본 결과다.
